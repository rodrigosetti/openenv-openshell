# v0.1.0 — prepared alpha release

This is the first prepared `openenv-openshell` package. It has not been
published to production PyPI. Publication requires the M3 acceptance gate,
I13 publishing validation, and I14 release verification. Package preparation
does not close those gates or establish production readiness.

## Included behavior

- `OpenShellProvider` implements OpenEnv's `ContainerProvider` lifecycle;
  existing async and sync clients use the OpenShell-managed HTTP/WebSocket
  route for health, reset, step, and state without client source changes.
- Exact caller command and environment, service routing, and explicit policy
  are submitted together. Invalid explicit inputs fail before create; policy
  failures never fall back to broader permissions.
- Cleanup covers normal close and partial startup failure, supports repeated
  stop calls, and reports sanitized errors. `keep_sandbox=True` explicitly
  leaves the sandbox running for operator cleanup.
- Generated sandbox names fit the 0.1.2 gateway's 19-character limit.
  Configuration supports workspace, explicit names, service selection,
  provider instances, labels, and resource requests. Run metadata records
  sandbox identity, image reference, service URL, and explicit policy digest.
- Documentation includes the EchoEnv quickstart, coding-agent policy demo,
  configuration, image preparation, troubleshooting, and security evidence.

## Installation and artifacts

Python 3.11+ is required. The supported dependency pair is **OpenEnv 0.6.0**
and the official **OpenShell SDK/gateway 0.1.2**. The SDK is a separately
installed runtime prerequisite: use the exact official wheel URL and SHA-256
in [`requirements-openshell.txt`](../../requirements-openshell.txt), following
the [installation guide](../releases.md#sdk-and-gateway-prerequisites).
The adapter rejects missing or mismatched SDKs before gateway access. Do not
substitute the incompatible PyPI SDK.

The wheel contains the Python package, typing marker, license, and metadata.
The sdist also includes the SDK prerequisite file, lockfile, Makefile, SPEC,
documentation, examples, scripts, and tests. Neither contains the Beads ledger,
local environments, caches, or gateway credentials. The wheel's README refers
to repository documentation; obtain the sdist or checkout to run examples.

## Known limitations and release blockers

- Cleanup is name-based: a create collision or name reuse can cause deletion
  of an unowned sandbox. SEC8a must be resolved before release acceptance.
  Identity-aware deletion waiting does not make the delete request conditional
  on ownership. See the [security review](../security-review.md#cleanup-blast-radius).
- The local native VM lane has no established sandbox-specific process/thread
  budget. It must not be represented as availability isolation for hostile
  workloads. Resource requests do not prove runtime enforcement. See the
  [capacity scope decision](../process-capacity.md).
- Runtime support is validated on the local Apple Silicon native arm64 VM
  lane with the documented images. Local image IDs are not pullable registry
  digests; arbitrary images and other compute drivers are unverified.
- Remote mTLS service routes require a TLS client certificate that unmodified
  OpenEnv clients cannot supply. They are unsupported and fail explicitly with
  `ServiceAccessError`. OIDC/edge authentication, long idle sessions, and
  reconnect behavior remain unverified.
- Server argv, required environment, and working directory handling are
  caller-supplied. OCI startup metadata is not resolved automatically.
- Raw environment values are readable by workload processes. Prefer reviewed
  OpenShell provider-backed credentials; log redaction does not hide secrets
  from the workload.
- Trusted verification, automatic policy generation, and a dedicated doctor
  CLI are outside this release's implemented API.

Consult the [compatibility matrix](../compatibility-matrix.md),
[security guide](../security.md), and [release procedure](../releases.md)
before selecting a deployment. Live test evidence applies to the documented
image/driver/policy, not every workload.
